## Runtime Data Area 5가지 영역

| 영역 | 공유 범위 | 저장 내용 |
|------|-----------|-----------|
| **Heap** | 모든 스레드 공유 | 객체 인스턴스, 배열, String Pool |
| **Stack** | 스레드별 독립 | 스택 프레임 (지역변수 + 오퍼랜드 스택 + 프레임 데이터) |
| **Metaspace** | 모든 스레드 공유 | 클래스 메타데이터, 메서드 바이트코드, 상수풀 |
| **PC Register** | 스레드별 독립 | 현재 실행 중인 JVM 명령어 주소 |
| **Native Method Stack** | 스레드별 독립 | JNI를 통한 네이티브 메서드 호출 정보 |

### Metaspace vs PermGen (Java 8 이전)

| | PermGen (Java 7 이전) | Metaspace (Java 8+) |
|---|---|---|
| 위치 | Heap 내부 (고정 크기) | 네이티브 메모리 (OS 영역) |
| 기본 크기 | 64~256MB 고정 | 제한 없음 (OS 메모리까지 확장) |
| OOM | `PermGen space` | `Metaspace` |
| 문제 | 클래스 많으면 크기 예측 어려움 | 무제한 증가 가능 → `MaxMetaspaceSize`로 제한 권장 |

## 질문하며 읽기 — 실행 결과

### 1. `new Object()`를 호출하면 메모리에서 무슨 일이 일어나는가?

```
obj class: java.lang.Object
obj hashCode: 498931366
```

**과정:**
1. **Class Loading**: `Object` 클래스가 아직 로드 안 됐으면 ClassLoader가 로드 → Metaspace에 클래스 메타데이터 저장
2. **메모리 할당**: Heap의 Eden 영역에서 객체 크기만큼 공간 확보 (TLAB이 있으면 스레드 로컬 버퍼에서 빠르게 할당)
3. **객체 헤더 초기화**: Mark Word(해시코드, GC 나이, 락 상태) + Klass Pointer(Metaspace의 클래스 메타데이터 참조)
4. **참조 저장**: Stack의 지역변수 슬롯에 Heap 객체의 참조(주소) 저장

```
Stack                    Heap (Eden)
┌──────────┐            ┌──────────────────┐
│ obj: 0xAB│───────────▶│ [Object Header]  │
└──────────┘            │  Mark Word       │
                        │  Klass Pointer ──┼──▶ Metaspace의 Object 클래스 정보
                        └──────────────────┘
```

### 2. `int x = 10` vs `Integer x = 10`은 어디에 저장되는가?

```
primitiveX = 10 (Stack에 값 직접 저장)
boxedX == boxedY ? true (캐시 범위 내 → 같은 객체)
Integer(200) == Integer(200) ? false (캐시 범위 밖 → 다른 객체)
```

| 선언 | 값 저장 위치 | 이유 |
|------|-------------|------|
| `int x = 10` | **Stack** (지역변수 슬롯에 값 자체) | 원시 타입은 객체가 아님. 참조 없이 값만 저장 |
| `Integer x = 10` | **Heap** (Integer 객체), Stack에 참조 | 오토박싱 → `Integer.valueOf(10)` 호출. -128~127은 캐시 재사용 |

```
Stack                    Heap
┌────────────┐
│ primitiveX │ = 10 (값 자체)
├────────────┤          ┌──────────────┐
│ boxedX     │─────────▶│ Integer(10)  │ ← Integer 캐시
├────────────┤     ┌───▶│              │
│ boxedY     │─────┘    └──────────────┘
├────────────┤          ┌──────────────┐
│ a (200)    │─────────▶│ Integer(200) │ ← 캐시 범위 밖, 새 객체
├────────────┤          └──────────────┘
│ b (200)    │─────────▶┌──────────────┐
│            │          │ Integer(200) │ ← 또 다른 새 객체
└────────────┘          └──────────────┘
```

### 3. String 리터럴 `"hello"` vs `new String("hello")`

```
literal1 == literal2       ? true  (같은 String Pool 참조)
literal1 == newStr         ? false (Pool vs Heap 별도 객체)
literal1.equals(newStr)    ? true  (값은 동일)
newStr.intern() == literal1? true  (intern → Pool 참조 반환)
```

| 방식 | 저장 위치 | 설명 |
|------|-----------|------|
| `"hello"` | **String Pool** (Heap 내부) | 컴파일 타임에 상수풀에 등록. 같은 리터럴은 같은 참조 |
| `new String("hello")` | **Heap** (일반 객체 영역) | 항상 새 객체 생성. Pool의 `"hello"`와 별도 |
| `intern()` | **String Pool** 참조 반환 | Pool에 같은 값이 있으면 그 참조, 없으면 등록 후 반환 |

```
Stack                    Heap
┌──────────┐            ┌─── String Pool ───┐
│ literal1 │───────────▶│ "hello" (0x10)    │
├──────────┤       ┌───▶│                   │
│ literal2 │───────┘    └───────────────────┘
├──────────┤            ┌───────────────────┐
│ newStr   │───────────▶│ "hello" (0x20)    │ ← 별도 객체
└──────────┘            └───────────────────┘
```

### 4. 왜 Heap은 공유이고 Stack은 스레드별인가?

```
[T1] shared=1, localVar=100, thread=worker-1
[T2] shared=2, localVar=200, thread=worker-2
[Main] shared 최종값=2 (두 스레드가 Heap 객체를 공유)
```

**Stack이 스레드별인 이유:**
- 메서드 호출/리턴 순서가 스레드마다 다르다 → 스택 프레임 순서가 독립적이어야 함
- 스레드별 독립이므로 동기화 불필요 → 빠르다
- `localVar`는 각 스레드의 Stack에만 존재 → 다른 스레드에서 접근 불가 (thread-safe)

**Heap이 공유인 이유:**
- 객체는 여러 스레드가 함께 사용해야 하는 경우가 많다 (예: DB 커넥션 풀, 공유 자료구조)
- 객체를 스레드마다 복사하면 메모리 낭비 + 데이터 일관성 유지 불가
- 대신 동시 접근 시 동기화 필요 → `synchronized`, `volatile`, `Atomic*` 등

```
Thread-1 Stack     Thread-2 Stack          Heap
┌────────────┐    ┌────────────┐    ┌──────────────┐
│ localVar=100│   │ localVar=200│   │ shared[0] = 2│
│ (독립)      │   │ (독립)      │   │ (공유)       │
└──────┬─────┘    └──────┬─────┘    └──────────────┘
       │                 │                ▲   ▲
       │                 └────────────────┘   │
       └──────────────────────────────────────┘
```

## JVM 메모리 현황 (기본 옵션으로 실행)

```
Max Heap   : 6144 MB   ← 물리 메모리(24GB)의 약 1/4
Total Heap : 388 MB    ← 현재 JVM이 OS에서 확보한 Heap
Free Heap  : 383 MB    ← 아직 미사용
Used Heap  : 4 MB      ← 실제 사용 중
```

- `Max`는 `-Xmx`로 설정 가능 (기본값은 물리 메모리의 1/4)
- `Total`은 실제 확보한 크기 (`-Xms`로 초기값 설정)
- 사용량이 `Total`을 넘으면 `Max`까지 자동 확장, `Max`도 넘으면 OOM
